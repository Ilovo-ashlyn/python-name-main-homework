# 复盘

## 哪些是 AI 做的

- 把实验文档通读一遍，把考核形式、5 项交付物、两道题的验收标准整理成清单
- 拆任务、定文件清单和实现顺序
- 写代码：Excel 清洗统计、FastAPI 三个接口、pytest 用例、README、requirements.txt
- 核环境里已装 / 缺哪些库、生成运行截图、同步仓库和提交
- 三份 `ai_logs` 的框架和素材

一开始就说清楚两条：报错要能直接看懂、别甩英文 Traceback；三张汇总表得跟手算的数对上。后面 `ledger_api.py` 里多个没用的 `RecordOut`、总览的「合计」被当成一笔销售重复累加，都是核对时揪出来改掉的。

## 哪些是我自己定的

- 工作方式：先出计划再编码、一个文件一个文件写、每写完一个汇报、没批准的库不装、不重构无关代码
- 范围：第一题全做；第二题只做核心，SQLite、认证、前端都不做
- 六个字段全当「关键字段」，缺一个就删行；三张汇总表必须都能跟手算的 270 对上
- `requirements.txt` 单独列一份；`report.xlsx` 和 `run_output.png` 一起交，方便直接看结果，截图没压缩
- 验收我自己跑了：`python excel_report.py`（19→12、270.00）、`pytest -q`（24 passed）、`uvicorn` 真起服务打 HTTP 请求、SHA-256 前后比对、打开 `report.xlsx` 看四张表

## 人工审过的风险

| 风险 | 这次具体是什么 | 怎么处理的 |
|---|---|---|
| 数据被改 / 口径不一致 | 原始文件被误写、清洗顺序影响统计 | 全程只读；输出路径和输入路径相同时直接拒绝；SHA-256 前后比对；三张汇总表交叉核对都是 270 |
| 脏输入搞崩程序 | 空文件、缺列、非法参数 | 5 类文件异常给中文可读报错；Pydantic + 业务校验返回 422 且不落库 |
| 并发 | 自增 id 重复、记录丢失 | 一把 `threading.Lock` 管住写入和自增；8 线程写 16 条断言 id 连续不重复、总数不丢 |
| 范围跑偏 | 擅自装库、动到别的实验 | 只新装 4 个批准过的库；Starlette 建议的 `httpx2` 没装；前面作业和 exp2 / exp3 一行没改 |
| 性能 | 全量遍历、锁内拷贝 | 样例才 19 行，这个量级不用优化；`GET` 在锁里只做一次快照，过滤和分页放锁外，真上大数据再考虑换存储 |
| 持久化 | 重启或多进程就丢数据 | 题目允许内存存储，就选了内存，README 里写明了这个取舍。单进程做实验够用，我接受 |

## 做得不够的地方

- 第二题没做持久化，只是单进程内存版。时间够的话想加个 SQLite，哪怕最简表结构，重启还能查到。
- 时间主要花在接口的异常分支和测试上，第一题反而比较顺；60 分钟紧，最后截图和提交有点赶。
- 完整聊天记录没一开始就导出，只留了要点摘要，这个应该在做的时候同步存。
- 重来一次的话，我想更早自己接管验收那一步：先把 270 手算出来、把要测的异常列好，再让 AI 写代码，这样后面不用回头改口径。

## 一句话

AI 主要承担了写代码和整理的活，判断留在我这边：范围划到哪、口径怎么定、什么时候算做完，都是我自己核过才放行的。
