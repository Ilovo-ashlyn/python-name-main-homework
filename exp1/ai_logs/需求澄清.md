# 需求澄清

动手写代码之前先把题目拆了一遍，主要是怕做到一半发现方向不对。下面这份是当时列给自己、后来也直接发给结对 AI 的范围，相当于提前把边界划死。

## 要做什么

两道 Python 实操题，限时 60 分钟。要求跑得起来、能自己验证、输入不合法也别直接崩，另外得把跟 AI 协作的过程留下来。评分按结果、过程、验证、风险、复盘这五项算。

- 第一题必做（40 分）：把 `sales_raw.xlsx` 清洗统计，生成四个 sheet 的 `report.xlsx`
- 第二题做核心部分：FastAPI 记账接口，`POST /records`、`GET /records`、`GET /summary`

## 输入输出

| 项 | 第一题 | 第二题 |
|---|---|---|
| 输入 | `sales_raw.xlsx`，六个字段：日期、销售员、产品、数量、单价、地区；里面混了空值、重复行、数量≤0 的脏数据 | JSON 流水：金额、类型、分类、日期；查询条件：类型、分类、日期区间、分页 |
| 输出 | `report.xlsx` 四张表：明细清洗后 / 按销售员 / 按地区 / 总览 | 新建返回 201 和带自增 id 的记录；列表返回 `{total, page, page_size, items}`；汇总返回 `{income, expense, balance}` |
| 副作用 | 原始文件只读，不能改 | 数据放内存，不落盘 |

## 边界

- 清洗顺序定死：先删关键字段缺失 → 再剔数量≤0 → 最后六字段全同的去重；销售额 = 数量 × 单价
- 文件不存在、0 字节、只有表头、缺列、清洗完一行不剩，都要给看得懂的中文报错，不能甩 Traceback
- 接口校验：金额 > 0；类型只能是收入/支出；日期 `YYYY-MM-DD`；非法参数给 4xx，最好带结构化的错误信息
- 分页 `page ≥ 1`、`1 ≤ page_size ≤ 100`；日期区间不能前大后小
- 环境 Python ≥ 3.10。库只批准 pandas、openpyxl、fastapi、uvicorn、pytest、httpx（httpx 是 TestClient 要用）
- 并发写不能把 id 写重、不能丢记录，能说清楚怎么保证就行

## 怎么算做完

1. `python excel_report.py` 一条命令出报表，三张汇总表加起来要跟手算的对得上
2. 脏输入不崩，报错看得懂；`sales_raw.xlsx` 跑前跑后哈希一样
3. 接口能真起服务、能调通，非法请求的状态码对得上
4. `pytest` 覆盖正常用例，另外至少两个边界/异常
5. 交运行截图、协作记录、复盘

## 几个我自己定的

- 先出计划清单，我确认了再动手写代码，没让 AI 上来就写。
- 一个文件一个文件写，每写完一个说清楚改了什么、用哪条命令验。
- 库只装批准过的那几个，没批准的不许装；Starlette 后来提示换 `httpx2`，也只记下来没动。
- 不碰前面几份作业和 exp2、exp3 的代码。
- 第二题的脚本叫 `ledger_api.py` 而不是 `app.py`，因为 exp2 的 Streamlit 已经叫 `app.py` 了，怕混。
- 「关键字段」我按六个字段全算：任何一个空了，这行都没法正确算销售额或者参与分组，留着没意义，直接删。
- 第二题「做核心」我理解成：三个接口 + 校验 + 并发保护就够了，SQLite 持久化、登录认证、前端页面都不做，题目没要求，时间也不够。
- 亲自验的节点我留了这几个：跑脚本看 19 行变 12 行、总额 270；`pytest -q` 看 24 passed；真的 `uvicorn` 起一次服务，用 HTTP 请求打一遍；比对 `sales_raw.xlsx` 的 SHA-256；截图存 `run_output.png`。
