# 实验 2：数据看板的设计与实现（基础部分）

业务场景：校园超市 2026 年 3—8 月销售数据监控。**只完成基础实验任务 1~5**，进阶与扩展部分不做。

运行（进入本目录后）：

```bash
streamlit run app.py
```

浏览器打开 http://localhost:8501 即可看到看板。PyCharm 里选右上角运行配置「实验2 | 数据看板（Streamlit）」点 ▶；看完点 ■ 停止服务。

> **注意**：Streamlit 是网页服务，不能像普通脚本那样 `python app.py`。若误选了 PyCharm 自动生成的 `app` 配置（或直接点编辑器里的绿色 ▶），会因缺少 `ScriptRunContext` 在控制台反复刷警告，且不会有网页。`app.py` 入口已做兼容：检测到这种运行方式会自动改用 `streamlit run` 重启，两种方式现在都能打开看板。

依赖：`pip install streamlit pandas plotly`；本机 `D:\pycharm\venv` 已装好 streamlit 1.67.0 / pandas 3.1.1 / plotly 7.1.0。

## 任务 1：需求分析与版面设计

看板回答四个问题：整体卖了多少、哪类商品和哪个校区卖得好、销售随时间怎么变、逐日明细是什么。

配色方案：主色 `#1F6FEB`（蓝，标题／指标）、辅助色 `#F59E0B`（橙，图表）、背景色 `#F5F7FA`（浅灰），卡片与图表区用白底。

简易版面草图：

```text

│ [总销售额] [总订单数] [日均销售额] [销售额环比]        │
```

## 任务 2：数据准备与预处理

`data.csv` 是 AI 生成的模拟数据（固定随机种子），字段为 `日期, 品类, 校区, 销售额, 订单数`，共 191 行，含 5 个品类、3 个校区、6 个月份，其中故意混入 7 条脏数据。

`app.py` 的 `load_data()` 完成预处理：日期转 `datetime`（无效日期剔除）→ 数值列转数值（空值剔除）→ 剔除 `销售额 <= 0`／`>= 20000`、`订单数 <= 0` 的异常值 → 去重复行 → 补 `月份` 列。清洗后 **184 行**，页面顶部会显示剔除条数。三个维度：时间＝日期／月份，分类＝品类／校区，数值＝销售额／订单数。

## 任务 3 / 4：基础图表与看板整合

| 组件 | 实现 |
| --- | --- |
| 数据卡片 | `st.metric`：总销售额、总订单数、日均销售额（平均值）、销售额环比（增长率） |
| 柱状图 | `px.bar`：各品类销售额对比 |
| 环形图 | `px.pie(hole=0.45)`：各校区销售额占比 |
| 折线图 | `px.line`：6 个月销售额趋势 |
| 明细表格 | `st.dataframe`：清洗后逐日明细 |

四个模块用 `st.container(border=True)` 分区，`st.columns` 排版，自定义 CSS 统一背景、卡片边框、字体和图表配色；页面 `layout="wide"`。全程为**静态看板**，不含筛选、联动、自动刷新等进阶功能。

## 任务 5：验证与总结

- 本地启动 `streamlit run app.py`，服务健康检查通过，四大模块与四张图表均正常渲染；成品截图见 `dashboard.png`。
- 数据核对：清洗后 184 行、6 个月份、5 个品类、3 个校区；四个卡片的数值与各图表汇总口径一致。
- 遇到的问题与解决：
  1. 图表中文与浅灰背景冲突 → 统一设 `Microsoft YaHei` 字体、图表白底。
  2. 新版 Streamlit 的 `st.plotly_chart` 已默认 `width="stretch"` → 不再传旧参数 `use_container_width`。
  3. CSV 带中文且需兼容 Excel → 用 `utf-8-sig` 保存，读取时显式指定 `encoding="utf-8-sig"`。
  4. 在 PyCharm 里把 `app.py` 当普通 Python 脚本运行 → 控制台反复刷 `missing ScriptRunContext` 警告且没有网页；在入口用 `get_script_run_ctx(suppress_warning=True)` 检测，没有服务上下文时自动以 `streamlit run` 重新启动。
